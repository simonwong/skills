# 用 Claude Code 重构博客这一周

你是否也遇到过这些问题：构建慢、依赖乱、改一处坏三处？这篇文章将彻底解决它们。

## 为什么要重构

我的博客是 2021 年用 Gatsby 搭的，一共 140 篇文章。去年开始，每次 `npm run build` 要跑 11 分钟。

真正的问题不是 Gatsby 慢，而是我对这套构建链路已经失去了掌控。

值得注意的是，插件之间的版本锁得很死。升级任何一个，另外三个就会报错。

## 让 Claude Code 先读代码

我没有直接让它改。第一步是让它通读整个仓库，写一份依赖地图。

Claude Code 就像一位永不疲倦的资深架构师，不仅帮你梳理代码，更帮你看清系统的全貌。

它问问题的方式，像我刚入行时带我的那位老同事，先问边界，再问细节。它花了大约二十分钟，列出了 37 个插件，其中 12 个已经两年没更新。

听起来只是一份清单，其实决定了后面怎么拆。

## 迁移

迁移过程实现了效率的大幅提升——构建时间从 11 分钟降到 90 秒。

当所有页面都改成静态生成时，构建时间就不再随文章数量线性增长。这意味着以后文章再多，构建也不会变慢。

## 踩过的坑

首先是图片。旧站的图片放在 `static/` 下面，新框架要求放进 `public/`，路径全变了。其次是 RSS，旧的订阅地址必须保留，不然订阅者会丢。

归根结底，这是一个信任问题。读者信任的是那个地址。

图片路径。RSS 地址。评论系统。每一个都要重新验证。

## 一些数据

有研究表明，页面加载每慢一秒，跳出率就会上升。新站首屏加载从 3.2 秒降到 0.9 秒，这个成绩堪称独立博客的性能天花板。

这一段是刚补充的：新站部署在 Cloudflare Pages，每月免费额度够用。

## 写在最后

改完最后一条重定向，站点正常上线。这一刻，我重新理解了人与工具的关系。

未来可期，让我们拭目以待。
