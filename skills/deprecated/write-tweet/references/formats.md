# 结构骨架

段落先后顺序的候选。材料没有的段落删掉，多出的按同一顺序插入，段落数由材料决定；材料同时符合几种时，选最具体那件事排最前的那种；没有合适的按材料自然顺序写。结尾项有作者自己的内容才写，内容说完直接停。

## 短推

### 判断加依据

一句判断，一句依据。依据是数字、对比、原话或一个具体场景。

> agent 调工具出错，先查工具描述。
> 我这周三次误调用，两次是 description 把参数含义写反了。换模型没用，改描述就好了。

### 结果加动作

结果放第一行，带数字或可见变化，后面说做了什么。

> 同一套测试，换了 harness 通过率从 31% 到 62%。
> 模型没动，加了一个 hook 拦截写文件，失败后自动回滚再跑一次。

### 具体问题

遇到的问题写具体，给出目前的解法；没解决就说没解决。

> Claude Code 的 /goal 我试了三次，两次空转到 token 用完。
> 把目标改成「测试全过且 lint 干净」才跑通。模糊目标它判断不了。

### 作品或现象加说明

先呈现作品或现象，再说一句它是什么、怎么来的或哪里值得看；有疑问就带上。

> 同一段提示词跑了四个模型，只有一张把手画对了。
> 画对的那张，提示词里其实没提手。

### 疑问

疑问写具体：什么情况下、看到什么、哪里想不通。没有答案就停在疑问。

> agent 记住了上次的错，这次为什么还是绕回去了？
> AGENTS.md 里写了先跑测试，它先改测试再改回来，等于绕了一圈。

## 长推

### 转述原文

给一篇或几篇文章、演讲或发布，整理成推文。

1. 分段转述原文要点，每段一个点，按原文的重要程度排；几篇时按来源或主题分段，段首给足指代。
2. 结尾：自己的判断、存疑或会怎么用；没有就停在要点。

> agent 每犯一次错，就把修复写进 AGENTS.md，这套做法叫棘轮。
>
> 同一个模型，只换 harness，SWE-bench 分数差一倍。围绕模型的 prompt、hooks、sandbox 和恢复路径合起来就是 harness。
>
> 棘轮的落点是每行规则都能追溯到一次真实事故。模型升级时删过时的约束、补新的。
>
> 我自己的 AGENTS.md 也是这么长起来的，只是没这么自觉。回去把没有事故来源的规则删掉试试。

### 经历拆解

做成或做砸了一件事。

1. 结果，能带数字就带。
2. 关键动作或转折，每条一两句，按时间或依赖顺序。
3. 结尾：最核心的一条经验，或还没弄懂的地方。

### 清单

一次给多条信息。

1. 主题和范围：选了哪类、几条；来自测试时写测了多少、用了多久。
2. 每条附一句为什么，不只列名字。
3. 结尾：自己的选择和理由；介绍几个不同方向时可以不选。

### 教程

教读者完成一件具体的事。

1. 做完得到什么。
2. 前提：版本、账号、依赖。
3. 步骤，每步写动作和可见结果。
4. 结尾：最容易卡的一步，卡住怎么判断。

### 前后对比

状态有明显变化。

1. 前一行 before，后一行 after。
2. 中间改了什么，每条一句；只是观察到变化、原因还没确定时写明。
3. 结尾：最值得说的一点，出乎意料或还没弄懂的地方。

### 观点

对一个有争议的问题有立场。

1. 立场，一句说清。
2. 依据，每条独立成段。
3. 边界：什么情况下不成立。
