# 开头

读者从第一行进入这条推文。方式由内容决定，可以给事实、判断、问题、情境、作品或真实反应；字数由内容定。入口可以从正文里提一句到最前，也可以另写。

## 判断标准

- 读到第一行，读者知道这条在说什么，或知道接下来要看什么。
- 第一行的承诺正文兑现：说了结果就交代怎么来的，预告了几点就给几点。
- 有助于理解、语气或节奏的铺垫保留；空转、夸大或制造正文不兑现的悬念的删。
- 结合配图、视频或被引用的推文读第一行。

## 入口

| 入口 | 示例 |
| --- | --- |
| 结果或数字前置 | 同一套测试，换了 harness 通过率从 31% 到 62%。 |
| 直接判断 | agent 调工具出错，先查工具描述。 |
| 自己遇到的问题 | /goal 我试了三次，两次空转到 token 用完。 |
| 反应加事件 | 这也行。Bun 用了十天把底层从 Zig 换成了 Rust。 |
| 原文里最反直觉的一句 | agent 每犯一次错，就把修复写进 AGENTS.md。 |
| 正在做的事 | 昨天把三个项目的 CLAUDE.md 合成了一份。 |
| 反差（两端都是具体事） | 换更贵的模型没帮上忙，改一行 description 好了。 |
| 作品或现象 | 同一段提示词跑了四个模型，只有一张把手画对了。 |
| 疑问 | agent 记住了上次的错，这次为什么还是绕回去了？ |

## 容易空转的开头

这些第一行换任何内容都能套：先表态再说事（「不受欢迎的观点：」「有一说一」）、禁令和讣告（「别再 X 了」「X 已死」）、数字接悬念（「我用 N 天做到 X，但真正起作用的只有一个」）、破折号留白、收藏引导、接不上具体事的感叹（「太离谱了」）。遇到时看正文是否兑现，兑现不了的换成直接给实质信息。
