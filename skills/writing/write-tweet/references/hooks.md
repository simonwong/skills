# 开头

只管第一行。第一行从正文里挑：找最具体、最出乎意料的那句提到最前面，约 20 到 40 字。

## 判断标准

- 第一行带本条的实质信息：一个事实、一个结果、一个判断。只有承诺、悬念或态度，实质内容要到正文才出现的，是模板。
- 单独读第一行，读者知道这条在说什么。
- 删掉第一行，第二行当不了第一行。当得了，说明第一行是预热，删掉。
- 第一行里的每个词删掉一个，意思都会变。不变的词删掉。
- 正文兑现第一行。第一行说了结果，正文就交代怎么来的。

## 入口

候选只来自正文里已有的句子，入口用于认出哪句放最前。

| 入口 | 示例 |
| --- | --- |
| 结果或数字前置 | 同一套测试，换了 harness 通过率从 31% 到 62%。 |
| 直接判断 | agent 调工具出错，先查工具描述。 |
| 自己遇到的问题 | /goal 我试了三次，两次空转到 token 用完。 |
| 反应加事件 | 这也行。Bun 用了十天把底层从 Zig 换成了 Rust。 |
| 原文里最反直觉的一句 | agent 每犯一次错，就把修复写进 AGENTS.md。 |
| 正在做的事 | 昨天把三个项目的 CLAUDE.md 合成了一份。 |
| 反差（两端都是具体事） | 换更贵的模型没帮上忙，改一行 description 好了。 |

## 已被认出的模板

这些第一行换任何内容都能套：先表态再说事（「不受欢迎的观点：」「有一说一」）、禁令和讣告（「别再 X 了」「X 已死」）、预告个数（「N 个教训」）、数字接悬念（「我用 N 天做到 X，但真正起作用的只有一个」）、破折号留白、收藏引导、接不上具体事的感叹（「太离谱了」）、自问自答。都换成直接给实质信息。
