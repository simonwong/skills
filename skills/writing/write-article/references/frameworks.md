# 行文提纲与节奏

提纲和节奏一起设计。方法可以不用，模板可以更换，这篇文章读下来是什么感觉必须想清楚。

## 行文提纲

提纲写文章怎样读下来：从什么地方进入，接下来具体讲什么，哪部分最值得展开，什么时候解释或举例，最后停在哪里。关键材料挂在对应位置。两个例子，演示提纲的粒度：

> 资料比较：从容易混淆的地方进入 → 提出比较问题 → 按几个关键差异展开 → 用材料解释这些差异 → 说明目前能判断什么、还不能判断什么。

> 过程分享：交代起因 → 展示最值得看的尝试 → 解释其中一个变化或发现 → 停在当前结果或未完成的问题上。

有判断要论证时，把判断、支持它的材料、读者可能追问的问题放在一起，让提纲看得出推理怎样推进。卡在某处时，用例子把判断落地，用原因解释现象，用条件限定建议，或回应一个会影响结论的异议；选当前缺的那一种。

## 节奏

节奏是读者在每个位置的感受：知道自己在看什么，有理由往下读，在需要时能消化。节奏可快可慢：问题已明确时尽快进入解释或办法；缺少背景时先补必要知识；难点放慢，次要内容一句带过；一个例子可以是读者消化内容的空间。

## 候选结构

从下表选一种或改一种，也可以按材料自己安排。借鉴别人的文章时，取抽象的结构和讲述方法；措辞和口吻见 [个人风格](voice.md)。

| 结构 | 适用情况 | 讲述顺序 | 展开重点 |
| --- | --- | --- | --- |
| 从误解进入解释 | 读者听过一个概念，容易与另一个混淆，且有依据表明这种混淆存在 | 指出混淆 → 给出关键区别 → 用例子解释 → 说明区别为什么重要 | 篇幅留给最难理解的差别 |
| 问题 → 步骤 | 问题明确，读者需要操作办法 | 问题 → 步骤 → 结果 | 步骤能执行，适用条件和结果清楚 |
| 问题 → 洞察 → 解法 | 有发现，想解释为什么这样做 | 问题 → 哪条观察改变了理解 → 由此得出的做法 | 洞察与解法之间的推导 |
| 介绍 → 理解 → 办法 | 读者需要先补背景与原理 | 介绍问题 → 补足必要知识 → 给出办法 | 只补采用建议所需的知识 |
| 结论 → 理由 → 证据 | 读者想先知道判断 | 先给判断 → 条件与理由 → 反例与取舍 | 判断的边界 |
| 比较选择 | 几个对象之间要做选择 | 统一比较条件 → 逐项差异 → 能判断什么、不能判断什么 | 影响选择的差异 |
| 过程分享 | 一次尝试值得讲出来 | 起因 → 关键尝试 → 变化或发现 → 当前结果 | 最值得看的那一步 |
| 观察与作品分享 | 一个现象值得讨论，尚无定论 | 现象 → 值得注意的细节 → 几种解释 → 当前倾向和疑问 | 细节和观察本身 |
