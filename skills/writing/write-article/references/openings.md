# 开头与收尾

## 开头

开头让读者尽快知道这篇在讲什么、为什么值得往下看。

入口的位置和作用在提纲里已定，这里定具体措辞：从正文中挑一个具体入口。例子只演示措辞，其中的经历、事件与结果须由当前材料支持。

| 入口 | 示例 | 后面接什么 |
| --- | --- | --- |
| 一件正在做的事 | 昨天整理项目时，我又花了一遍时间找上次停在哪。 | 实际困境、尝试与发现 |
| 一个意外结果 | 配置只改了一行，原先失败的请求就通过了。 | 改了哪里，为什么会有这个结果 |
| 一个具体疑问 | 同一份配置，为什么换台机器就跑不起来？ | 排查过程，或资料给出的解释 |
| 一个有边界的判断 | 这套记录方式适合我自己用，团队协作还没试过。 | 判断依据、收益与限制 |
| 外部材料或讨论触发 | 最近看到一条推文说这个用法要废弃，我当时的回复是…… | 原文或各方说了什么，自己怎么看 |
| 结论或结果前置 | 先把几个结论放在前面。 | 三两条结论，随后逐条给依据 |
| 一个反常的具体事实 | 这个岗位年薪接近二十万美元，招的不是程序员。 | 事实的来路，以及它为什么反常 |
| 一个现象 | 最近生成的视频里，人物走路都有一种飘的感觉。 | 现象的细节，几种解释 |
| 一组作品 | 这周用同一个提示词跑了四个模型，结果差别比我想的大。 | 作品逐个展示，作者的观察 |
| 一个容易混淆的概念 | 上下文窗口和记忆经常被当成一回事，我自己也混淆过。 | 关键区别和例子 |

## 主语换成读者

标题、开头和结尾定稿前看一遍主语。主语是产品、工具或作者时，试着换成读者，信息不变：

- 产品：这次更新加了本地导出。
- 读者：你的旧笔记现在能从这里迁出去了。

换完仍是事实才用；材料只支持产品视角时，改成读者会问的问题，由正文回答。作者的过程是主角时保留作者视角。

## 标题

标题从正文实际写出的内容里挑，承诺不超过正文；主语按上一节检查。给用户两三个备选时，说明各自强调什么。

## 收尾

结尾停在正文支持的地方：一个做法、一个取舍、一个限制、当前结果，或一个还没解决的问题。结尾之后的固定段落见 [个人风格](voice.md)。

开头出现过的物件在结尾回来时，读者对它的理解已经改变才回来。
