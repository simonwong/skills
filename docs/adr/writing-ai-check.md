# writing-ai-check 的设计决定

共同决定（分工、调用方式、不用数字阈值）见 [writing-skills.md](writing-skills.md)。具体条目和流程以 `SKILL.md` 为准，这里只记为什么这样定。

## 诊断表达，不判断由谁创作

不输出 AI 率或概率评分，只指出具体位置的具体表达问题，给出保留原意的改法。流畅和严谨本身不算问题，改写时保持原稿的流畅和严谨。

理由：身份判断建立在整体统计特征上，规整、流畅、术语密集的技术文本本来就容易被判为机器生成，而这正是本仓库的主要场景。身份判断既不准，也不告诉作者该改哪里。靠添加卡顿、口语或假犹豫制造的真实感本身就是另一种痕迹。

## 只管 AI 味

内容、材料、论证、篇幅、外部事实核实归写作 skill，个人风格归各自的 `voice.md`。输入和判断依据只有稿件本身，单独使用时也能判断。

理由：混进内容评审后，报告里一半是 AI 味，一半是“写得不够好”，作者分不清哪些是模型痕迹，哪些是内容取舍。

## 编号清单，单文件

每处命中对应一个编号，说不出编号的不报。每条给触发标记、保留边界，每种形态一对 Bad／Good；条目扩大适用范围时改说明，例子保持一种形态一对。误伤由每条的保留边界和“不算 AI 味”清单控制，不由全局阈值控制。

全部内容在一份 `SKILL.md` 里。每次检查都要过全部条目，没有可跳过的分支，拆成 `references/` 只增加读取次数。

外部参考里的新形态优先并入现有条目；出处写在 README 的实现参考列表。

## 不收的候选

- 顿号并列、三连排比、重复句首、被动句、句长接近：中文对照语料实测人机无差异，或倍率太低。
- 序数词小标题：有指代功能的排版选择。
- 名词化改回动词：人类名词化多于 AI，口语化改写属于制造真实感。
- 不相称的精确细节、案例凑数、泛化举例、绝对量词、虚假讲故事：要评内容与事实。
- 敬称“您”：人称是作者的选择。
- 黑话词表、AI 高频词表：这些词在作者叙述里是普通用语，按词表替换会改掉作者用词。
- 四字格排比、“进行＋动词”、被字句堆叠、强凑三段式：与上面同类。
- 情绪曲线太光滑、没有犹豫、句子节奏均匀、知识全部输出、脆弱感服务于论点、结论包装成协议：要求制造不完美，或判的是内容。
- 严重度分级、追问式改写：与默认直接交付冲突。

## 默认直接交付定稿

默认交付定稿，会删掉观点或拿不准的地方列为待定、定稿里保持原文。指文件时直接改文件，靠版本管理回退。

理由：每处改后文字在报告里已经写好，再等一轮确认才拿到全文，收益小。删观点是作者的决定，所以单列待定。

## 逐段扫描，不设上限

按段扫描，命中逐处记，统计按编号列次数，多轮检查每轮从文件重读、各给一行统计。

理由：只说“通读全文逐条过”时，报告常常只列几处，长稿后半篇的命中被略过，同一条出现多次只报一两处。统计让覆盖可以核对。

## 用例

用例放在仓库根目录 `evals/writing-ai-check/`，格式同 skill-creator 的 `evals.json`，不随 skill 安装。改条目、流程或交付格式后先跑用例。
