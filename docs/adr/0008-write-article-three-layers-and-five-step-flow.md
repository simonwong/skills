# ADR-0008：write-article 分为流程、写法经验、个人风格三层，流程改为五步

- 状态：已采纳
- 日期：2026-09-17
- 取代：ADR-0003

## 背景

ADR-0003 的三阶段流程把「材料能串成一条实际过程」写成准备阶段的完成标准；讲述框架要求每章标出有用、共鸣或有意思，三样都不占就删；开头切入要求具体疑问必须是作者遇到过的；复查冷读第一问是「哪一段让我相信作者确实做过」。这些要求合在一起，把各种文章都推向亲身实践和经验复盘：没有亲历的资料解读、观察稿、作品分享被反复索要经历，或被硬加实用收益和成熟结论。

问题不在方法本身，而在它们被写成了每篇文章的验收门槛，适用条件被省略。

另一个问题是文件职责混在一起。流程、写作方法和作者个人风格改动频率不同：流程随协作方式变，方法随实际稿件积累，个人风格只随作者本人的文字更新。没有分层时，改一处要通读全部文件确认没有冲突。

## 决策

### 三层

| 层 | 文件 | 内容 | 改动时机 |
| --- | --- | --- | --- |
| 流程 | `SKILL.md` | 基本约定、默认读者、入口判断、五步默认路径与完成标准、每步读哪个参考文件、子代理与 `writing-ai-check` 的调用、排版 | 协作方式变化；默认读者随作者本人的定位变 |
| 写法经验 | `references/topics.md`、`frameworks.md`、`genres.md`、`openings.md`、`review.md` | 选题启发工具、行文提纲与节奏、候选结构、各写法的常见缺口与检查、开头与收尾入口、复查项 | 从实际稿件中提炼出新方法，或发现旧方法被误用 |
| 个人风格 | `references/voice.md` | 作者认可的表达原则、样例、固定句式 | 作者本人的文字或修改反馈，规则见 `skills/writing/AGENTS.md` |

三层的关系：流程说何时读哪个文件；写法经验是启发工具，每条带适用情形，不作为评分表；个人风格只来自作者，与他人的口吻分开。

单一真源：「写法」一词只指 `genres.md` 的节名，其他文件引用时用同名；行文提纲和节奏的定义在 `frameworks.md`，`SKILL.md` 只写完成标准；排版要求在 `SKILL.md`；同一条规则写作时的说法在 `SKILL.md` 或 `genres.md`，复查时的说法在 `review.md` 或 `genres.md`「检查」，各一处。子代理复查不共享上下文，`SKILL.md` 的交接清单列出它需要的参考文件和章节，references 增减时同步这份清单。

一条经验进入文件前先归类：事实底线进 `SKILL.md` 基本约定或对应步骤；特定写法的要求进 `genres.md` 对应一节并写明适用情形；通用讲述方法进 `topics.md`、`frameworks.md`、`openings.md` 或 `review.md`；个人偏好进 `voice.md`；一次性修改不进文件。一篇文章出问题时按这个顺序归类，再决定是否进长期规则。

### 流程

默认路径：确定选题方向 → 定向补充素材 → 设计行文提纲与节奏 → 展开写作 → 整体修改与交付。入口按输入状态选起点：只有想法、材料多而散、内容全但讲述乱、已是好草稿，各自从不同一步开始。五项按需合并、跳过、回退。

与 ADR-0003 的差别：

- 先定方向再定向检索，替代先盘点到「够了」再谈方向。检索结果可以推翻方向。
- 素材完成标准从「串成实际过程」改为「主要内容能讲清，关键判断有材料或标为推断」。
- 行文提纲与节奏成为独立一步。提纲写出文章怎样读下来；节奏在提纲阶段安排篇幅重点、解释、例子、转场和收尾，在复查阶段查拖沓、重复和突跳。节奏的定义只在 `frameworks.md` 一处。
- 开头的作用在提纲阶段定，措辞和标题在正文稳定后定。ADR-0003 「先定开头会让正文去凑」的判断保留。
- 子代理复查改为条件分支：新写全文或改动超过一半时开；局部修改在当前上下文复查。

沿用 ADR-0003 的部分：材料来路四类（亲历 / 检索 / 已核实 / 推断）；查不到的数据写「未找到」；材料不足时先自己检索再问用户；用户停止投入时按现有材料收窄并说明。

### 方法降为启发工具

HKRR（快乐、知识、共鸣、节奏，取自影视飓风 Tim）、三种转发动机（对我有用、感同身受、喜闻乐见，取自潘乱）、读者起点句式、结构模板、主语换读者、段末删句，每条写明适用情形。HKRR 的前三项与三种转发动机是同一件事，文件里只保留三种反应的问法；节奏单独成节。不计分、不凑项、不逐段贴标签。阅读价值不等于转发价值。

结构模板只记抽象结构：适用情况、讲述顺序、展开重点、使用提醒。别人的措辞、故事和内容不进模板。记入新结构时，检查它换几个题目是否仍成立，写清适用与不适用的情形。

涉及产品或工具的稿件，复查标准是三条：厂商说法是否被写成作者结论、是否只有卖点没有解释、是否写了材料里没有的确定收益。缺点和批评按材料写，不作为独立性的证明。

## 影响

- ADR-0004 的拆分依据不变。按读取时机新增 `references/topics.md`（步骤 1 读），文件标题随职责调整：讲述框架 → 行文提纲与节奏，体裁专项 → 写法专项，开头切入 → 开头与收尾。
- ADR-0001、ADR-0005 的调用关系不变。
- 校准靠实际稿件，覆盖六种输入：没有亲历的资料解读、只有少量感受的初步观察、AI 作品分享、需要严谨解释的深度文、只需局部修改的好草稿、检索推翻最初判断。看 AI 是否仍索要不必要的经历、是否强加收益和结论、能否先给清楚的提纲、原意是否保留、作者要花多少精力改到愿意发表。字数、公式覆盖度、AI 自评分和单篇传播数据不作为依据。
- `voice.md` 后续按 `skills/writing/AGENTS.md` 的规则补作者认可的样稿和修改对照，这次没有新增。通用写法（考虑读者门槛、借鉴取结构）从 `voice.md` 移到 `review.md` 和 `frameworks.md`；借鉴时保持作者口吻的那一半仍在 `voice.md`。
- HKRR 与三种转发动机的出处记在 README 的实现参考列表。
