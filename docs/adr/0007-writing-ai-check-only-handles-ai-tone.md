# ADR-0007：writing-ai-check 只处理 AI 味，按编号清单诊断

- 状态：已采纳
- 日期：2026-09-16

## 背景

`writing-ai-check` 的判断标准里混进了内容与论证评审：内容单薄时指出缺口、论证是否失去重点、结论是否超出正文范围、第一人称经历是否写得空、感受能否承担证明责任。这些是 `write-article` 复查的职责。混在一起的结果是，单独用它检查一篇稿件时，报告里一半是 AI 味，一半是「这篇写得不够好」，作者分不清哪些是模型痕迹，哪些是内容取舍。

判断标准按篇章、句子、词表、事实四个层级分文件，同一种痕迹散在两三处，验收按「看了哪里」而不是「查了什么」。还带了一条与实测相反的规则：连续几句字数接近视为模具。对照语料测句长离散度，人机无差异。

两个外部参考给了可借的形态。[lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone) 用中文对照语料实测了哪些特征成立、哪些不成立，每条有触发标记和正反例。[humanizer](https://github.com/blader/humanizer) 把英文 AI 味编成 25 条，全局编号，按强弱排序，标明哪些一处即报、哪些需要同段有其他命中。

## 决策

`writing-ai-check` 只找可定位的 AI 味，按编号认，不按感觉认。每一处报告都对应一个编号。

明确不管的：内容、材料、论证、篇幅；外部事实核实；个人风格。材料与内容归 `write-article`，个人风格归 `voice.md`。

痕迹编成 23 条，分五组，强的在前，每条固定给触发标记、Bad／Good 对照、保留边界。一条只有一种形态时给一对 Bad／Good，有多种形态时每种形态一对，Good 只用原文已有的实词。标「需同伴」的同段（D 组是同一节）另有命中才报。

- A 铺垫代替陈述：翻案腔、对着空气辩论、起手式与提示语、单句收尾与碎片句、深刻感金句。
- B 抒情与拔高：拟人化喻体、刻意修饰、拔高、借来的权威、概括盖住已有数据。
- C 句法与标点：破折号揭晓、段首零主语评论、相邻句结构同款、过长前置定语、句首前置壳、句首连接词当路标、「这意味着」式复述、为避重复而换名。
- D 篇章模具：模具重复、首尾超出正文、列表化。
- E 格式与残留：装饰性格式、对话残留。

全部内容在一份 `SKILL.md` 里，没有 `references/`。ADR-0004 把判断标准推到 reference 的依据是渐进披露，只有部分分支才读的材料放到文件后面；这个 skill 每次诊断都要过全部 23 条，没有可跳过的分支，拆分只增加读取次数和一份与标题重复的索引。

`SKILL.md` 流程在前，23 条在后，并内置「不算 AI 味」清单：问句、比喻本身、句内排比、句长参差、被动与长句、重复全称、正文序数词、顿号并列、作者的怪细节与矛盾感受。这张表防止 skill 把正常写法当痕迹改掉。

流程四步：标出命中、起草改写、检查草稿、汇报。默认只汇报，但汇报时每处已经给出改后文字，用户说继续才出定稿。改写可以合并、拆分段落，标题层级、章节顺序、列表、表格、引用和代码块位置不动。

外部参考的归属写在仓库 README 的实现参考列表，不写进 `SKILL.md`。

## 影响

- ADR-0004 中 `writing-ai-check` 的 reference 划分对这个 skill 失效，它是单文件；ADR-0001 里「特征清单只存在于 `writing-ai-check/references/`」的位置改为 `SKILL.md`，`write-article` 仍不复制。
- 默认只诊断（ADR-0001）。诊断已含改写草稿，第二步只是交付。
- 报告一处一条：位置、引文、编号加条目名、改后文字。编号加条目名代替 ADR-0002 里的「说明影响」，条目本身就是依据。删掉后失去支撑的句子在报告里注明由作者定。
- 不收的候选及理由：顿号并列，对照语料倍率低于门槛；序数词小标题，有指代功能的排版选择；三连排比、重复句首、被动句，中文实测人机无差异；名词化改回动词，人类名词化多于 AI，且口语化改写属于 ADR-0002 排除的制造真实感；不相称的精确细节、案例凑数、泛化举例、绝对量词，判断它们要评内容与事实；敬称「您」，人称是作者的选择，原文是什么就是什么；黑话词表，心智模型、降本增效这类词在作者叙述里是普通用语，按词表替换会改掉作者用词。
- 朗读检验放在「检查草稿」一步，不作为独立类别。
