# ADR-0006：X 推文写作独立为 write-tweet

- 状态：已采纳
- 日期：2026-09-14

## 背景

X 推文与公众号长文的写作约束不同：读者在第一行决定停留还是划走，短推要求精炼，平台不渲染 Markdown，读者对模板化开头的识别速度远快于长文。把它作为 `write-article` 的一种体裁，会让长文的三阶段协作、章节主线和排版规则全部落到一条几十字的推文上。

## 决策

新增 `write-tweet`，与 `write-article` 平级，同为显式调用（ADR-0005）。

- 输入分两种场景：用户自己写的文字走顺稿，只改错别字、语病、事实核查、衔接和排版，长度不变，除非用户传长短参数；外部材料走成文，整理后按骨架写。产出都是一条成稿，写前不出方案供选。
- 长度由参数决定：`short`、`long`；不传时按内容判断。用户显式设置优先。
- 成文场景按名调用 `/writing-ai-check`，方向与 ADR-0001 一致：单向调用，不复制特征清单。顺稿场景在用户要求时调用，因为作者手写稿的问题集中在错别字和衔接，不在 AI 味。
- reference 按 ADR-0004 拆分：开头、结构骨架、个人风格各一份。个人风格独立于 `write-article/references/voice.md`，两者不共享文件，因为推文口吻（反应词、无固定结尾）与长文不同。voice.md 的依据只能是作者本人写且认可的文字；AI 代写后未经认可的稿件不算，否则风格文件会把 AI 味当成作者习惯固定下来。维护规则写在 `skills/writing/AGENTS.md`。
- 反应词默认不用，材料自带或用户要求时才用一个，避免同一形状反复出现。
- 转述外部文章的推文采用「第一行事实、分段转述、结尾自己的判断」结构，正文与作者判断分离。正文不写原作者名和链接，来源由引用转发或首条回复带出。

## 影响

- 三个写作 skill 都是显式调用，description 不进上下文；用户要记住三者各自的触发场景。
- 两份 voice.md 需各自维护；作者风格变化时要分别更新。
- `writing-ai-check` 的翻案腔规则会命中常见的反差式推文开头。`write-tweet` 不申请豁免，而是要求反差两端为具体事物并紧接依据，与该规则的保留边界一致。
