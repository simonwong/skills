# ADR-0004：reference 按单一职责拆分，个人风格独立成文件

- 状态：已采纳
- 日期：2026-09-10

## 背景

两个 skill 的判断标准数量不小：讲述框架、体裁要求、开头写法、风格偏好、复查项、结构特征、句子特征、禁用词句、事实边界。早期版本把它们堆在主文件里，主文件同时承载协作流程和大量清单，流程被清单淹没；合并成一两个大 reference 后，改一处要通读整个文件才能确认没有冲突。

个人风格还有一个额外问题：它更新频率最高，也最不适合与通用写法混在一起。

## 决策

主文件只放流程、完成标准和调用关系，判断标准全部推到 `references/`，按职责拆分，一个文件只回答一类问题。

- `write-article`：讲述框架、体裁专项、开头切入、个人风格、复查。
- `writing-ai-check`：篇章结构、句子表达、禁用词句、事实与表达边界。

拆分依据是调用时机，不是主题大小。同一时点由同一角色读的内容合成一个文件：风格一致性复查与冷读都由复查子代理在初稿后执行，因此合并为 `review.md`。`writing-ai-check` 的四份在诊断时全部读，拆分只为让每份能独立维护。

个人风格独立为 `write-article/references/voice.md`，与通用写法分开，单独更新。特征清单只存在于 `writing-ai-check/references/`，`write-article` 不复制一份。

引用外部规范时给链接，不抄内容；排版遵循中文文案排版指北即属此类。

## 影响

- 改一条判断标准只动一个文件。
- reference 数量会随场景增加，主文件里的读取时机必须同步维护，否则出现无人读取的孤儿文件，或某个文件只有一半内容有人读。
- 每个 reference 都要能独立读懂，少量重复的前置说明是可接受的代价。
