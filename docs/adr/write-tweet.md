# write-tweet 的设计决定

共同决定（分工、调用方式、三层结构、不用数字阈值）见 [writing-skills.md](writing-skills.md)。具体步骤和规则以 `SKILL.md` 与 `references/` 为准，这里只记为什么这样定。

## 独立成 skill

读者在第一行决定停留还是划走，平台不渲染 Markdown，读者识别模板化开头比长文快得多。长文的选题、素材、提纲确认和排版规则放到几十字的推文上都不合适，所以推文不作为 `write-article` 的一种写法，四步一口气做完。事实底线和 `write-article` 各写一份，保持自包含。

## 入口按本次要求

先按用户本次要求定处理方式（严格顺稿、压缩扩写重组、成文），再看材料够不够。没说范围时，用户自己写的文字默认严格顺稿；链接是资料，不改变修改范围。

理由：按材料划分场景时，用户要求压缩自己的稿子，正文照留、只在备注里建议删句；带参考链接的最小改稿被归入成文，修改范围反而扩大。

## 方法是启发工具

骨架、开头和说话位置都随材料定：骨架是候选，结尾项有作者自己的内容才写；有经历写经历，没有经历写转述、观察、判断、疑问或感受。反应词默认不用，材料自带或用户要求时才用一个。

理由：把“我试过，你参考”写成固定说话位置、结尾默认写自己的判断，会把每条推文推向亲测结论，作品分享、疑问、观察和资料整理没有位置。反应词每条都用，会让同一个形状反复出现。

## 事实与归属

他人的测试、解释和判断保留范围与归属，链接放在哪里不改变这条。何时交代归属只在 `SKILL.md` 基本约定定义，`voice.md` 只给句式。

理由：只保留来源方自报结果的归属时，别人在特定条件下的测试会被写成普遍结论。

## 不调用 writing-ai-check

理由见 [writing-skills.md](writing-skills.md)「分工与调用关系」。

反差式推文开头要求两端是具体事物并紧接依据，与 `writing-ai-check` 翻案腔的保留边界一致，用户事后运行检查时不会被改掉。

## 校准

改规则后用五种输入校准：带参考链接的最小改稿、明确要求压缩的原稿、只有疑问的短帖、纯作品分享、无个人观点的资料整理。看是否越权改稿、是否索要不必要的经历、归属是否保留、篇幅参数是否执行。
