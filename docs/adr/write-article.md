# write-article 的设计决定

共同决定（分工与互不调用、调用方式、三层结构、不用数字阈值）见 [writing-skills.md](writing-skills.md)。具体步骤和规则以 `SKILL.md` 与 `references/` 为准，这里只记为什么这样定。

## 流程：五步默认路径，节点内灵活

五步是默认路径，按输入状态选起点，按需合并、跳过、回退。每步给完成标准，不规定内部动作顺序。

理由：输入可能是几句话，也可能是一份详细草稿，前置工作差别很大。拆成九步时模型按格子填内容，没法按输入调整。

- 先定方向再定向检索，检索结果可以推翻方向。先盘点到“够了”再谈方向，检索没有目标。
- 材料不足时继续补，不硬停；用户不再投入时按现有材料收窄，交付时写明。硬停只是把责任推回给用户。
- 标为推断、加限定语都不代替依据。限定语会被拿来掩盖没有依据的判断。
- 开头的作用在提纲阶段定，措辞、标题和收尾在正文稳定后定。先定开头会让正文去凑，这是套路化开头的来源。
- 新开的节和独立成段的补充限在已确认的选题方向里，方向之外的先问用户。模型会自己补“注意事项”“不适用场景”一类的节，作者没打算写。
- 读者按篇定，写给另一类人时在选题方向里写明。默认读者套到入门科普上，技术深度、例子和产品名都要返工。
- 单句的例外和技术分支按读者判断，复查时直接改，不进“先问用户”的闸门。闸门扩到单句会变成逐句提问。

## 复查

长文、主线重组或较大范围新增事实时开子代理复查，短稿和局部修改在当前上下文复查。子代理拉开距离，但要交接材料；短稿不值得这份成本。

`review.md` 不设冷读：它问的两件事由写法专项的检查和“作者表达”覆盖，通读由朗读承担。

## 不调用 writing-ai-check

理由见 [writing-skills.md](writing-skills.md)「分工与调用关系」。

## 方法是启发工具

HKRR（快乐、知识、共鸣、节奏）的前三项和三种转发动机（对我有用、感同身受、喜闻乐见）是同一件事，只保留三种反应的问法，节奏单独成节。出处记在 README 的实现参考列表。

结构模板只记抽象结构，别人的措辞、故事和内容不进模板。记入新结构前，检查它换几个题目是否仍成立。

理由：这些方法写成每篇的验收门槛时（每章标出有用、共鸣或有意思；开头的疑问必须是作者遇到过的），没有亲历的资料解读、观察稿、作品分享会被反复索要经历，或被硬加实用收益和结论。

## 校准

改规则后用实际稿件校准，覆盖六种输入：没有亲历的资料解读、只有少量感受的初步观察、AI 作品分享、需要严谨解释的深度文、只需局部修改的好草稿、检索推翻最初判断。看 AI 是否仍索要不必要的经历、是否强加收益和结论、能否先给清楚的提纲、原意是否保留、作者要花多少精力改到愿意发表。字数、公式覆盖度、AI 自评分和单篇传播数据不作为依据。
