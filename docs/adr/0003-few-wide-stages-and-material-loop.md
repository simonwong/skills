# ADR-0003：写作流程用少量宽阶段，材料靠循环补足

- 状态：已被 ADR-0008 取代
- 日期：2026-09-10（取代：2026-09-17）

## 背景

早期设计把写作拆成九个步骤，每步带完成标准，并在材料不足时硬停：列不出足够材料就不输出正文。

拆细步骤的问题是流程僵化，模型按格子填内容，无法根据输入形态调整。输入可能是几句话，也可能是一份详细草稿，两者需要的前置工作差别很大。

硬停的问题是把责任推回给用户就结束了。实际需要的是继续把材料找出来。

## 决策

流程节点少，每个节点内部灵活。三个阶段：理解与准备、确认方向、成文与迭代。每个阶段给完成标准，不规定内部动作顺序，由模型按输入形态决定怎么走。

阶段是默认路径，不是关卡。用户随时会在看过某一部分后提出修改意见，就地处理，不重跑前面的阶段。输入已经是成稿时，先确认改动范围和不可动的部分，只核实存疑处，不做全稿盘点。

材料不足时循环补足，不停止：

1. 先自己检索，把查到的内容作为线索交给用户。
2. 请用户补亲历、判断和检索覆盖不到的部分。
3. 用户补充后出现新缺口，再围绕它检索。
4. 用户确认够了，进入下一阶段。用户不再补充或让模型自己判断时，按现有材料收窄题目继续，交付时说明收窄了什么、还缺什么。

检索的作用是给用户提供入口和参照，由用户决定哪些值得展开。它不替代用户的经历和判断。不设追问轮数上限，由双方共同判断何时充分。

成文阶段内部有一处固定顺序：正文、开头、结尾、标题、排版。开头和标题从正文实际写出的内容里挑；先定它们会让正文去凑，这正是套路化开头的来源。

## 影响

- 模型有较大自由度，输出质量依赖完成标准写得够不够清楚。
- 没有硬停意味着材料始终不足时不会中止，需要在交付时说明收窄了什么、还缺什么。
- 三阶段划分与九步方案不兼容，早期设计稿已删除。
