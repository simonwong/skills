# ADR-0009：write-tweet 按本次要求定处理方式，方法降为启发工具

- 状态：已采纳
- 日期：2026-09-18
- 部分取代：ADR-0006

## 背景

ADR-0006 按材料把输入分成顺稿和成文两种场景，提示语里的动词不参与判断。用户要求压缩自己的稿子时，正文照留、只在备注里建议删句；带参考链接的最小改稿因为同时有文字和外部材料被归入成文，修改范围反而扩大。

个人风格文件把「我试过，你参考」写成固定说话位置；补素材只追问做了什么、结果是什么、哪里出乎意料；自查要求「换个署名这条就不成立」；第一行要求逐词不可删、候选只来自正文已有句子；骨架的结尾项默认是自己的判断、选择或最出乎意料的一点。这些合起来把每条推文推向亲测结论，作品分享、疑问、观察和资料整理没有位置。

来源处理有三处不准：只有来源方自报的结果保留归属，别人在特定条件下的测试结果会被写成普遍结论；AI 味交接固定说「来源在被引用的推文里」，但发布方式有引用转发、首条回复、链接在正文三种；顺稿保留拿不准的事实、原句照留，交付又说用户不回复也能直接发。

## 决策

### 入口按本次要求

先按用户本次要求定处理方式，再看材料够不够：只改错字顺句是严格顺稿；压缩、扩写、重组、重写保留原意、用户用词和指定内容，只做要求的操作；从关键词、方向、链接或别人的文章成文。未说明范围时，用户自己写的文字默认严格顺稿，哪怕零散或只有一行疑问；只有关键词、链接或别人的文章时默认成文。链接是资料，不改变修改范围。`short` / `long` 控制篇幅，压缩和扩写在正文执行，不以备注代替；严格顺稿带参数时按参数压缩或扩写，其余仍按严格顺稿。

流程收成四步：理解本次要求 → 看已有内容 → 写一稿 → 自查并交付。推文不做长文的选题、素材、提纲确认，几十字的推文四步一口气做完。

### 三层与 write-article 对齐

流程在 `SKILL.md`；写法经验在 `references/formats.md`、`hooks.md`；个人风格在 `references/voice.md`。新规则的归类顺序沿用 ADR-0008：事实底线进 `SKILL.md` 基本约定；段落组织进 `formats.md`；入口方法进 `hooks.md`；个人偏好进 `voice.md`。事实底线与 write-article 各写一份，skill 保持自包含，ADR-0006 不共享文件的决定不变。

### 方法降为启发工具

- 骨架是候选：材料没有的段落删掉，没有合适骨架时按材料自然顺序写；结尾项有作者自己的内容才写。新增「作品或现象加说明」「疑问」两种短推；转述原文可以是几篇；清单说明主题或范围，不默认来自测试；前后对比区分观察到的变化和已有依据的归因。
- 开头由内容决定方式和字数，入口可以从正文里提一句，也可以另写；有助于理解、语气或节奏的铺垫保留。容易空转的开头列表保留，用法改为看正文是否兑现。检查开头时结合配图、视频或被引用的推文。
- 删去「换个署名就不成立」自查。一条推文围绕一个主要分享点，几个关联的观察可以放在一条里。
- 说话位置随材料定：有经历写经历，没有经历按材料写转述、观察、判断、疑问或感受。作者的关注点写成描述，不作为选题门槛。
- 节奏两个方向都查：铺垫多余，以及跳得太快、少了关键指代。长推段落可以承担背景、解释、例子或转折，不要求每段独立成条。

### 事实与归属

他人的测试、解释和判断保留范围与归属，不写成普遍结论或作者亲测；链接放在哪里不改变这条。拿不准的事实先查，查不到先在正文里限定，限定不了问用户，删是最后手段；严格顺稿下没能限定的原句照留，交付为带待确认项的稿。归属何时交代只在 `SKILL.md` 基本约定定义，`voice.md` 只给句式。转述型定义为主要内容来自别人的文章、演讲或推文；多来源时首条回复列全部链接。近期产品功能、版本和数字查官方或原始来源，不靠常识核查。

### AI 味检查

仍按名调用 `/writing-ai-check`，方向与 ADR-0001 一致。短推和一般改写在当前上下文调用；长推、较大改写或用户要求时交给子代理，交接时给出本次实际的发布方式、归属语指向的来源，以及要它做的事。自查在当前上下文完成，交付只列待确认项、改动说明和发布安排。严格顺稿在用户要求时调用，沿用 ADR-0006 的理由。

## 影响

- ADR-0006 保留的部分：独立 skill 与显式调用、长度参数、`voice.md` 独立维护且只来自作者认可的文字、反应词默认不用、来源由引用转发或首条回复带出。被取代的部分：两场景按材料划分、转述型结尾必须是自己的判断、成文一律交子代理做 AI 味检查。
- `voice.md` 的关注点描述来自作者对创作范围的说明，措辞待作者确认后按 `skills/writing/AGENTS.md` 的规则补样例。
- README 的 write-tweet 描述随入口更新。
- 校准用五种输入：带参考链接的最小改稿、明确要求压缩的原稿、只有疑问的短帖、纯作品分享、无个人观点的资料整理。看是否越权改稿、是否索要不必要的经历、归属是否保留、篇幅参数是否执行。
